# GGdown 启动与发行体积优化设计

## 意图与依据

落实本次对话中用户要求优化的四项评估结论：启动统计、引擎与页面就绪分离、Python 依赖精简、历史引擎清理。原始报告位于 `.cache/performance-audit/优化评估.md`，原始 C# 测量位于 `.cache/performance-audit/20261024-092102/results.json`。

基线：安装包 62.89 MiB，应用 169.52 MiB，引擎 62.60 MiB。每作者 10 条完成任务、没有脏标记时，全量统计重算在 1,000 作者下约 7 秒，5,000 作者下约 34 秒。未更新引擎的内容校验约 1.0–1.25 秒，首次引擎安装约 5.8 秒。以上均为本机组件测量，不是界面冷启动时间。

## 方案与取舍

1. 局部优化现有架构：沿用统计脏标记，拆分就绪任务，精简实际不使用的 Python 依赖，增加版本保留策略。改动可分别测试，保留现有安装体验；本计划推荐并细化此方案。
2. 通过共享 .NET/Windows App SDK 运行库缩小安装包：可能带来更大的应用体积收益，但增加系统前置依赖及安装分支，暂不采用。
3. 全面引入 Trim/NativeAOT、常驻 Python 工作进程：涉及 WinUI、EF、反射及进程协议兼容性，没有对应收益测量，暂不采用。

保留自包含离线安装、保留当前版本与一个回退版本是本计划提出的默认取舍，供用户审阅；不视为用户曾明确指定的要求。

## 统计修复

- 保留 `RecalculateDownloadCountsAsync` 的全量修复语义及现有统计口径。
- 新增启动入口 `RepairOnStartupAsync(CancellationToken ct = default)`。
- 每个平台库使用 `SiteSettings` 内部键 `ggdown.stats-projection.version`，版本值为 `1`，表示该库已经完成一次全量校正。
- 无标记或版本不匹配时，校正该平台全部作者；只有全部成功后写入版本标记。中断后可重试。
- 已完成校正时，只处理 `StatisticsPending=true` 涉及的不同作者。每作者的统计更新与对应脏标记清除仍处于同一事务。
- 干净启动不修改作者 `UpdatedAt`，跨平台相同 ID 不相互影响。正常任务完成时继续维护统计。
- 页面仍须等待数据库迁移、队列恢复和必要的统计修复完成，不能通过删除数据库就绪等待换取速度。

## 启动并行与引擎门

- 全局库初始化、当前站点读取与引擎准备独立进行。
- 全局数据准备完后放行侧栏；队列恢复和统计修复结束后放行数据页面。
- 所有 Python 操作统一在 `RunnerEngine` 入口等待引擎初始化任务，先等待再读取解释器、脚本与依赖路径。
- 等待操作可取消，取消单个调用不取消全局初始化；初始化失败不会变成没有结果的永久等待。
- 引擎缺失或初始化失败时，浏览已有数据仍可用，需要引擎的操作显示具体错误；更新失败且有可用旧引擎时继续回退。
- 保留引擎内容 SHA-256 校验、复制后校验及协议 v1 hello 验证。本轮先移出页面关键等待链路，不降低损坏检测要求。

## 依赖和发行产物

- 从根依赖和锁文件中移除确认未使用的 `lxml`、`javascript`、`fastapi`、`uvicorn`、`openpyxl`、`pydantic`、`pyperclip`，连带移除不再被需要的传递依赖。
- 不升级 Python 3.13.7、gallery-dl 1.32.10 或抖音固定提交 `473c90ff70c663cfb69310fff2b8d5192f200661`。
- 用实际第三方模块及三站适配器测试验证依赖闭包，避免只检查静态 import。保留仍需组件的 wheel 元数据和许可证，同步 `THIRD-PARTY.md`。
- 打包前过滤开发环境遗留的 Python 缓存，构建 smoke 使用 `-B` 避免再次生成缓存；不删除运行中的用户缓存。
- 在 `.cache` 下单独生成新安装包，保留当前 `dist` 作为体积对照。17.60 MiB 是候选依赖的未压缩体积，不作为压缩后安装包收益承诺。

## 引擎历史版本

- 当前活动版本及最近一个可用回退版本保留；仍被运行中操作使用的版本额外保留。
- Python 操作持有版本租约。清理前必须取得独占权限，未能确认闲置则跳过，不对运行目录做部分删除。
- 清理仅在引擎更新成功或复用成功后进行，不能破坏更新失败时的回退候选。
- 仅删除引擎 `versions` 下规范命名的真实目录；不跟随目录链接或重解析点，验证绝对路径边界。
- `.install-*` 仅清理超过 24 小时且可确认未被使用的遗留目录。清理失败记录诊断，不导致启动失败。
- 租约及维护元数据不属于引擎发行内容，不能使内容版本哈希在运行后发生变化。

## 验收与限制

- 为统计、初始化等待和版本清理先写失败测试，再实现并验证；用真实 SQLite 和临时引擎目录覆盖关键行为。
- C#、Python 全套测试通过；无凭据的发行 smoke 验证通过。缺少真实账号的在线场景明确列为未验证，不虚构下载成功。
- 同条件对比初始化后的干净统计修复，1,000/5,000 作者场景须显著快于 7/34 秒；目标小于 250 ms，作为基准检查而非脆弱的单元测试时限。
- 输出实际新旧安装包和解压体积差值，不把组件耗时相加当作完整应用启动时间。
- 最终必须成功执行 `dotnet build src/GGdown.App/GGdown.App.csproj -c Debug -p:Platform=x64`，并确认应用未锁住输出文件。
- 保留 DI 生命周期、数据库迁移、认证错误分类和 JSONL 协议，不上传、合并或发布安装包。
